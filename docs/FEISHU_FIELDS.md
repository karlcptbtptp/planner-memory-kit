# 飞书多维表格字段模板（legacy）

> v0.2.0 起，新项目推荐使用 MCP 团队记忆库作为远端事实源。本文档保留给仍在使用飞书多维表格主库的旧项目。

飞书多维表格是人工主库。投稿表要尽量短，只让投稿策划填写“知识本身”和必要分类；审核、状态、是否同步给 AI 都放在维护人的审核台。

## 投稿表字段

| 字段 | 类型 | 填写说明 |
|---|---|---|
| 标题 | 文本 | 一句话概括这条知识，方便搜索 |
| 摘要 | 文本 | 1-2 句话说清楚最重要结论 |
| 正文/文档链接 | 文本 | 写具体知识；已有飞书文档、报告或 runbook 时贴链接/路径 |
| 知识类型 | 单选 | `项目知识` / `原则` / `个人知识` / `其它` |
| 可见范围 | 单选 | `指定项目`=只给某个项目；`全策划`=所有项目可用；`仅本人`=个人知识，不进团队 AI 缓存；`其它` 需补充说明 |
| 适用项目 | 单选 | 项目代号，例如 `giftWeb` / `hwby` / `zgc` / `全项目` / `其它` |
| 敏感级别 | 单选 | `普通内部` / `项目敏感` / `禁止同步` / `不确定，请维护人判断` / `其它` |
| 来源 | 单选 | `自己经验` / `数据分析` / `策划案/需求` / `线上问题复盘` / `会议结论` / `AI 协作` / `其它` |
| 其它说明 | 文本，可空 | 只有前面选了 `其它` 或有特殊背景时再填 |

投稿表不设置默认值。选项里没有合适答案时，选 `其它`，再在 `其它说明` 补充；拿不准敏感级别时，选 `不确定，请维护人判断`。

## 审核台字段

这些字段由项目知识维护人填写，不应出现在投稿表里：

| 字段 | 类型 | 填写说明 |
|---|---|---|
| 标签 | 多选 | SQL口径 / 流程 / 踩坑 / 配置 / 经济系统 / 玩法设计 / 数据分析 / AI工具 / 共享记忆 / 其它 |
| 状态 | 单选 | `待审核` / `已批准` / `废弃` / `需要补充` / `其它` |
| 项目知识维护人 | 人员/文本 | 审核并对质量负责的人 |
| 审核时间 | 日期/文本 | 审核通过、驳回或要求补充的时间 |
| 审核意见 | 多行文本 | 维护人说明通过、驳回或禁止同步的理由 |
| 负责人 | 人员/文本 | 后续负责维护这条知识的人 |
| 是否同步给 AI | 单选 | `否` / `是`，只有维护人确认后才打开 |

## 系统字段

| 字段 | 类型 | 说明 |
|---|---|---|
| 提交人 | 创建人 | 系统自动记录 |
| 提交时间 | 创建时间 | 系统自动记录 |
| 最后更新 | 修改时间 | 系统自动记录 |

项目隔离靠 `可见范围`、`适用项目` 和同步命令里的 `--project` 实现：`适用项目=hwby` 且 `可见范围=指定项目` 的知识，只会进入 `--project hwby` 的本地缓存。
